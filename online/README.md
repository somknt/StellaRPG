# オンラインのアカウント（PC とスマホで同じアカウントを使う）

ゲームのアカウントとセーブデータを、無料のデータベース Supabase に保存します。準備は1回だけです。
準備ができるまでは、アカウントはその端末（ブラウザ）だけに保存されます。

## 保存される物

- ユーザー名
- パスワード：そのままでは保存されません。bcrypt で計算した、元に戻せない値だけが保存されます。
- セーブデータ：
  - プレイヤー名
  - 主人公（男の子・女の子）
  - 装備画面の設定（魔法パレット）
  - バトルコイン
  - クリアの記録・マイベスト

## 準備のしかた

1. **Supabase のアカウントとプロジェクトを作る**
   - https://supabase.com で、無料のアカウントを作ります。
   - 「New project」を押して、プロジェクトを作ります。
     - Name：何でもよい（例 `hoshinoko`）
     - Database Password：自分で決めて、メモしておく
     - Region：Northeast Asia (Tokyo)
     - 「Enable Data API」（Data API を使う）：チェックを入れたままにする（ゲームはこれで関数を呼ぶ）
     - 「Automatically expose new tables」：チェックなしでよい（関数を呼ぶ権限は SQL の中で渡している）
2. **表と関数を作る**
   - 左のメニューの「SQL Editor」を開きます。
   - このフォルダの `supabase_setup.sql` を全部コピーして、はりつけます。
   - 「Run」を押します。「Success」と出れば完了です。
   - 前の版の `supabase_setup.sql` を入れてあるプロジェクトでも、同じように全部はりつけて Run するだけです。
     - アカウント・セーブデータ・ログイン中の端末は、そのまま引きつがれます。
     - 途中でエラーになった時は、全部が元に戻ります（何も変わりません）。
     - 何回 Run しても大丈夫です。
     - 新しい版のあとに、まちがえて最初の版を Run してしまった時も、新しい版をもう一度 Run すれば直ります。
       - その間に作られたアカウントは `hk_private` に合わせます（同じユーザー名がある時は、前からある方を残します）。
       - `public` にできた表は消さずに、`hk_private.hk_accounts_backup_日時` のような名前で残します。
3. **確かめる（しなくてもよい）**
   - SQL Editor で、次の2行をはりつけて Run します。`permission denied` と出れば、表は公開鍵から見えていません。

     ```sql
     set role anon;
     select * from hk_private.hk_accounts;
     ```

   - 確かめたら、次を Run して元に戻します。

     ```sql
     reset role;
     ```

   - 「Project Settings」→「Data API」の「Exposed schemas」に `hk_private` が入っていないことも確かめます。
4. **URL と鍵をゲームに書く**
   - 「Project Settings」→「API Keys」（または上の「Connect」）を開きます。
   - 次の2つを写して、`js_version/js/online_config.js` に書き入れます。
     - **Project URL**（`https://〜.supabase.co`）を `url` に入れる
     - **Publishable key**（`sb_publishable_〜`）を `key` に入れる
       - 古いプロジェクトでは anon public key（`eyJ〜`）でもよい
   - **secret key と service_role key は、絶対に書かないでください。** 公開してはいけない鍵です。
5. コミットして公開すると、オンラインのアカウントになります。

## 知っておくこと

- 設定を書く前に作ったアカウントは、この端末だけのアカウントです。オンラインにした後は、アカウントを作り直してください。
  - アカウントを作る前に遊んでいた時のバトルコインとマイベストは、その端末で最初に作るアカウントに引きつがれます。
- 通信が切れている間も遊べます。変えた所（名前・装備・クリアの記録）はその端末に残しておき、つながった時に送ります。メインメニューの右上が「オフライン」になります。
- PC とスマホで同時に保存しても、両方の変更が残ります（保存の番号 `version` で、あとから書く方が読み直してから保存します）。
- 無料のプロジェクトは、1週間くらい誰も使わないと止まります（pause）。止まったら、Supabase の画面で「Restore」を押すと戻ります。
- パスワードを8回続けてまちがえると、そのアカウントには5分間ログインできなくなります。
  - ロックの間は、正しいパスワードでもログインできません。5分たつと、もう一度8回試せます。
  - 正しくログインできた時に、まちがえた回数は 0 に戻ります。
  - ロックの間も、もうログインしている端末は、ふつうに遊んで保存できます。
- パスワードを忘れた時に、メールで直すしくみはありません。メールアドレスを集めないためです。
  - 直す時は、SQL Editor で次を実行します。`ユーザー名` と `新しいパスワード` は書きかえてください。

```sql
update hk_private.hk_accounts
set pass_hash = extensions.crypt('新しいパスワード', extensions.gen_salt('bf', 10)), failed_count = 0, locked_until = null
where username_key = lower('ユーザー名');
```

## 安全のしくみ

### 表は API から見えない所にある

- 表と、中だけで使う関数は `hk_private` という schema にあります。
- ゲームの公開鍵（publishable / anon）から呼べるのは、`hk_register`・`hk_login`・`hk_load`・`hk_save`・`hk_logout` の5つの関数だけです。
- Supabase の Table Editor で表を見る時は、上の schema の選択を `hk_private` にしてください。
- 「Project Settings」→「Data API」の「Exposed schemas」に `hk_private` を入れないでください（入っていなければ大丈夫です）。

### 他人のデータは読めない・書けない

- 読み書きできるのは、ログインの鍵を持っているアカウントのデータだけです。鍵は推測できない長さで、サーバーには鍵のハッシュだけを保存します。
- ログインの鍵は 90 日有効で、使うたびに 90 日先へのびます。
- 1つのアカウントの鍵が 20 個より多くなった時は、30日より長く使っていない鍵から消します。30日以内に使った鍵は消さないので、PC とスマホなど、ふだん使う端末はログアウトされません。

### 回数制限

超えると、ゲームに「アクセスが多すぎます」と出ます。

| 何を | どこごとに | 回数 | 名前（`bucket`） |
| --- | --- | --- | --- |
| 登録を試す | 1つの IP | 10分に40回 | `register_try_ip` |
| 登録を試す | IP が分からない人みんなで | 10分に100回 | `register_try_noip` |
| アカウントを作る | 1つの IP | 1時間に20 | `register_ok_ip` |
| アカウントを作る | IP が分からない人みんなで | 1時間に30 | `register_ok_noip` |
| アカウントを作る | 全体 | 10分に100 | `register_ok_all` |
| ログインを試す（成功も数える） | 1つの IP | 10分に100回 | `login_ip` |
| ログインを試す（成功も数える） | IP が分からない人みんなで | 10分に300回 | `login_noip` |
| ログインをまちがえる | 1つの IP | 10分に30回 | `login_fail_ip` |
| ログインをまちがえる | IP が分からない人みんなで | 10分に100回 | `login_fail_noip` |
| セーブデータを読む | 1つのアカウント | 1分に240回 | `load_account` |
| セーブデータを書く | 1つのアカウント | 1分に120回 | `save_account` |

- 学校などで、同じ IP から大勢が使っても止まりにくいように、IP ごとの数は多めにしてあります。
- 数を変える時は、SQL Editor で次のように実行します（例：ログインを 10分に50回まで）。`supabase_setup.sql` をもう一度 Run しても、変えた数は上書きされません。

```sql
update hk_private.hk_rate_rules set max_hits = 50 where bucket = 'login_ip';
```

- IP の取り方：
  1. Supabase の前にある Cloudflare が付ける `cf-connecting-ip`
  2. それがない時は `x-forwarded-for` の最後の値（最後の値は Supabase 側が付ける物。最初の方の値は、呼ぶ人が自由に書けるので使いません）
  - どちらも、IP の形として正しい時だけ使います。IPv6 は、同じ家・同じ回線になる /64 ごとに数えます。
  - IP が分からない時も、制限はなくなりません。IP が分からない人みんなで1つの数を使います（上の表の「IP が分からない人みんなで」）。
- たくさんの IP を使う攻撃は、IP ごとの制限だけでは止まりません。そのために、全体の登録の数と、アカウントごとのロック（8回）もあります。

### セーブデータの保存

- 保存する時は、読んだ時の番号（`version`）が必要です。ほかの端末が先に保存していた時は保存せずに `CONFLICT` を返し、ゲームが読み直してから、もう一度保存します。どちらの変更も消えません。

### バトルコイン・マイベストのおかしな書きかえ

- サーバーは、保存するデータの形と値を確かめます。次のような保存は受けつけません（`BAD_DATA`）。
  - コインやクリアの回数が減る
  - クリアしていないのにコインが増える（1回のクリアで 500 枚まで）
  - 数ではないコイン、マイナスのタイム、1つのボスで 50 件より多い記録など
- ゲームのしくみはブラウザの中で動くので、ゲームを改造してクリアしたことにする書きかえまでは止められません。マイベストは自分のアカウントの記録なので、ほかの人の記録には影響しません。
- コインを使う所（お店など）を作る時は、`supabase_setup.sql` の `hk_private.check_data` の「コインは減らない」を直してください。
