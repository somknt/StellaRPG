# オンラインのアカウント（PC とスマホで同じアカウントを使う）

ゲームのアカウントとセーブデータを、無料のデータベース Supabase に保存します。準備は1回だけです。
準備ができるまでは、アカウントはその端末（ブラウザ）だけに保存されます。

## 保存される物

- ユーザー名
- パスワード：そのままでは保存されません。bcrypt で計算した、元に戻せない値だけが保存されます。
- セーブデータ：
  - プレイヤー名
  - 主人公（男の子・女の子）
  - 装備画面の設定（魔法パレット）
  - バトルコイン
  - クリアの記録・マイベスト

## 準備のしかた

1. **Supabase のアカウントとプロジェクトを作る**
   - https://supabase.com で、無料のアカウントを作ります。
   - 「New project」を押して、プロジェクトを作ります。
     - Name：何でもよい（例 `hoshinoko`）
     - Database Password：自分で決めて、メモしておく
     - Region：Northeast Asia (Tokyo)
     - 「Enable Data API」（Data API を使う）：チェックを入れたままにする（ゲームはこれで関数を呼ぶ）
     - 「Automatically expose new tables」：チェックなしでよい（関数を呼ぶ権限は SQL の中で渡している）
2. **表と関数を作る**
   - 左のメニューの「SQL Editor」を開きます。
   - このフォルダの `supabase_setup.sql` を全部コピーして、はりつけます。
   - 「Run」を押します。「Success」と出れば完了です。
   - 前の版の `supabase_setup.sql` を入れてあるプロジェクトでも、同じように全部はりつけて Run するだけです。
     - アカウント・セーブデータ・ログイン中の端末は、そのまま引きつがれます。
     - 途中でエラーになった時は、全部が元に戻ります（何も変わりません）。
     - 何回 Run しても大丈夫です。
     - 新しい版のあとに、まちがえて最初の版を Run してしまった時も、新しい版をもう一度 Run すれば直ります。
       - その間に作られたアカウントは `hk_private` に合わせます（同じユーザー名がある時は、前からある方を残します）。
       - `public` にできた表は消さずに、`hk_private.hk_accounts_backup_日時` のような名前で残します。
3. **確かめる（しなくてもよい）**
   - SQL Editor で、次の2行をはりつけて Run します。`permission denied` と出れば、表は公開鍵から見えていません。

     ```sql
     set role anon;
     select * from hk_private.hk_accounts;
     ```

   - 確かめたら、次を Run して元に戻します。

     ```sql
     reset role;
     ```

   - 「Project Settings」→「Data API」の「Exposed schemas」に `hk_private` が入っていないことも確かめます。
4. **URL と鍵をゲームに書く**
   - 「Project Settings」→「API Keys」（または上の「Connect」）を開きます。
   - 次の2つを写して、`js_version/js/online_config.js` に書き入れます。
     - **Project URL**（`https://〜.supabase.co`）を `url` に入れる
     - **Publishable key**（`sb_publishable_〜`）を `key` に入れる
       - 古いプロジェクトでは anon public key（`eyJ〜`）でもよい
   - **secret key と service_role key は、絶対に書かないでください。** 公開してはいけない鍵です。
5. コミットして公開すると、オンラインのアカウントになります。

## 知っておくこと

- 設定を書く前に作ったアカウントは、その端末（ブラウザ）だけのアカウントです。データは、下の「前からあるデータの引きつぎ」でオンラインに引きつげます。
- ほかの端末で遊んだ分は、ページに戻ってきた時（タブを開き直した・ウィンドウを選んだ）にサーバーから読みこみます。
- 通信が切れている間も遊べます。変えた所（名前・装備・クリアの記録）はその端末に残しておき、つながった時に送ります。メインメニューの右上が「オフライン」になります。
- PC とスマホで同時に保存しても、両方の変更が残ります（保存の番号 `version` で、あとから書く方が読み直してから保存します）。
- 無料のプロジェクトは、1週間くらい誰も使わないと止まります（pause）。止まったら、Supabase の画面で「Restore」を押すと戻ります。
- パスワードを8回続けてまちがえると、そのアカウントには5分間ログインできなくなります。
  - ロックの間は、正しいパスワードでもログインできません。5分たつと、もう一度8回試せます。
  - 正しくログインできた時に、まちがえた回数は 0 に戻ります。
  - ロックの間も、もうログインしている端末は、ふつうに遊んで保存できます。
- パスワードを忘れた時に、メールで直すしくみはありません。メールアドレスを集めないためです。
  - 直す時は、SQL Editor で次を実行します。`ユーザー名` と `新しいパスワード` は書きかえてください。

```sql
update hk_private.hk_accounts
set pass_hash = extensions.crypt('新しいパスワード', extensions.gen_salt('bf', 10)), failed_count = 0, locked_until = null
where username_key = lower('ユーザー名');
```

## 前からあるデータの引きつぎ

オンラインにする前に作ったアカウントのデータ（プレイヤー名・主人公・装備・バトルコイン・クリアの記録・マイベスト）は、その端末からオンラインに引きつげます。アカウントの画面に案内が出ます。

- **同じユーザー名とパスワードでログインする**：ふつうはこれだけです。
  - オンラインにそのユーザー名がなければ、同じユーザー名・パスワードでオンラインのアカウントを作って、データを入れます。
  - オンラインにもう同じユーザー名がある（スマホで先に作ったなど）時は、データを足し合わせます。
- **パスワードを忘れた**：オンラインにする前に、その端末で自動ログインしていた時だけ、「はじめて遊ぶ」で新しくアカウントを作ると引きつぎます。ユーザー名は同じでも、ちがっても大丈夫です。
- **ユーザー名が、オンラインではほかの人に使われていた**：「はじめて遊ぶ」で新しいユーザー名を作ると引きつぎます。
- **自動ログインしていた端末で、ちがうユーザー名にログインした**：メインメニューの「アカウント」に「この端末の『〜』のデータを入れる」が出ます。2回押すと入ります。

足し合わせ方：
- バトルコインとクリアの回数は足します（サーバーの決まりで、足すコインは1回のクリアで500枚まで）。
- マイベストは、両方の記録を合わせて速い順に残します。
- プレイヤー名・主人公・装備は、オンラインのアカウントにない時だけ入れます。

その他：
- パスワードが合わない、自動ログインもしていなかったアカウントは引きつぎません（1つのブラウザをほかの人と使っている時に、ほかの人のデータが入らないように）。
- 引きついだアカウントには印を付けるので、2回入ることはありません。その端末のデータは消さずに残ります。
- アカウントを作る前（アカウントのしくみができる前）に遊んだバトルの記録は、その端末で最初にログイン、またはアカウントを作ったアカウントに1回だけ入ります。
- データは端末ごと・ブラウザごと・サイトのアドレスごとにあります。PC とスマホの両方にデータがある時は、それぞれの端末で1回ずつログインすると、両方が足し合わされます。

## 安全のしくみ

### 表は API から見えない所にある

- 表と、中だけで使う関数は `hk_private` という schema にあります。
- ゲームの公開鍵（publishable / anon）から呼べるのは、次の関数だけです。
  - アカウント：`hk_register`・`hk_login`・`hk_load`・`hk_save`・`hk_logout`
  - マルチプレイ：`hk_mp_state`・`hk_mp_create`・`hk_mp_join`・`hk_mp_leave`・`hk_mp_kick`・`hk_mp_close`・`hk_mp_enter`・`hk_mp_ready`・`hk_mp_start`・`hk_mp_finish`
- Supabase の Table Editor で表を見る時は、上の schema の選択を `hk_private` にしてください。
- 「Project Settings」→「Data API」の「Exposed schemas」に `hk_private` を入れないでください（入っていなければ大丈夫です）。

### 他人のデータは読めない・書けない

- 読み書きできるのは、ログインの鍵を持っているアカウントのデータだけです。鍵は推測できない長さで、サーバーには鍵のハッシュだけを保存します。
- ログインの鍵は 90 日有効で、使うたびに 90 日先へのびます。
- 1つのアカウントの鍵が 20 個より多くなった時は、30日より長く使っていない鍵から消します。30日以内に使った鍵は消さないので、PC とスマホなど、ふだん使う端末はログアウトされません。

### 回数制限

超えると、ゲームに「アクセスが多すぎます」と出ます。

| 何を | どこごとに | 回数 | 名前（`bucket`） |
| --- | --- | --- | --- |
| 登録を試す | 1つの IP | 10分に40回 | `register_try_ip` |
| 登録を試す | IP が分からない人みんなで | 10分に100回 | `register_try_noip` |
| アカウントを作る | 1つの IP | 1時間に20 | `register_ok_ip` |
| アカウントを作る | IP が分からない人みんなで | 1時間に30 | `register_ok_noip` |
| アカウントを作る | 全体 | 10分に100 | `register_ok_all` |
| ログインを試す（成功も数える） | 1つの IP | 10分に100回 | `login_ip` |
| ログインを試す（成功も数える） | IP が分からない人みんなで | 10分に300回 | `login_noip` |
| ログインをまちがえる | 1つの IP | 10分に30回 | `login_fail_ip` |
| ログインをまちがえる | IP が分からない人みんなで | 10分に100回 | `login_fail_noip` |
| セーブデータを読む | 1つのアカウント | 1分に240回 | `load_account` |
| セーブデータを書く | 1つのアカウント | 1分に120回 | `save_account` |
| マルチプレイの関数（hk_mp_〜） | 1つのアカウント | 1分に400回 | `mp_account` |

- 学校などで、同じ IP から大勢が使っても止まりにくいように、IP ごとの数は多めにしてあります。
- 数を変える時は、SQL Editor で次のように実行します（例：ログインを 10分に50回まで）。`supabase_setup.sql` をもう一度 Run しても、変えた数は上書きされません。

```sql
update hk_private.hk_rate_rules set max_hits = 50 where bucket = 'login_ip';
```

- IP の取り方：
  1. Supabase の前にある Cloudflare が付ける `cf-connecting-ip`
  2. それがない時は `x-forwarded-for` の最後の値（最後の値は Supabase 側が付ける物。最初の方の値は、呼ぶ人が自由に書けるので使いません）
  - どちらも、IP の形として正しい時だけ使います。IPv6 は、同じ家・同じ回線になる /64 ごとに数えます。
  - IP が分からない時も、制限はなくなりません。IP が分からない人みんなで1つの数を使います（上の表の「IP が分からない人みんなで」）。
- たくさんの IP を使う攻撃は、IP ごとの制限だけでは止まりません。そのために、全体の登録の数と、アカウントごとのロック（8回）もあります。

### セーブデータの保存

- 保存する時は、読んだ時の番号（`version`）が必要です。ほかの端末が先に保存していた時は保存せずに `CONFLICT` を返し、ゲームが読み直してから、もう一度保存します。どちらの変更も消えません。

### バトルコイン・マイベストのおかしな書きかえ

- サーバーは、保存するデータの形と値を確かめます。次のような保存は受けつけません（`BAD_DATA`）。
  - コインやクリアの回数が減る
  - クリアしていないのにコインが増える（1回のクリアで 500 枚まで）
  - 数ではないコイン、マイナスのタイム、1つのボスで 50 件より多い記録など
- ゲームのしくみはブラウザの中で動くので、ゲームを改造してクリアしたことにする書きかえまでは止められません。マイベストは自分のアカウントの記録なので、ほかの人の記録には影響しません。
- コインを使う所（お店など）を作る時は、`supabase_setup.sql` の `hk_private.check_data` の「コインは減らない」を直してください。

## マルチプレイ（星の酒場）

バトルモードの「マルチプレイ」から入る、ほかの端末の人と遊ぶロビーです。オンラインのアカウントでログインしている時だけ遊べます。

### 準備

- 前の版の `supabase_setup.sql` を入れてあるプロジェクトでも、新しい `supabase_setup.sql` を全部はりつけて Run してください。マルチプレイの表と関数が足されます。アカウントとセーブデータはそのまま残ります。
- Run していない間は、酒場に入ると「サーバーの準備がまだです」と出て、パーティーを作れません。
- Realtime の設定はいりません（Supabase のプロジェクトに最初から入っています）。

### 遊び方

1. 南の魔法陣から酒場に出てきます。ほかの人の姿・名前・動きが見えます。
2. カウンターのマスターに話しかけて、「協力プレイ」（クエストを受注）か「PvP」（対戦相手の募集）を選びます。受けた人がリーダーです。
3. ほかの人は、扉の左のクエスト掲示板から「参加する」で入ります。協力プレイは4人まで、PvP は2人までです。
4. 自分のパーティーの扉だけが開きます。扉の上の数は、扉に入った人数です（自分のパーティーの人にだけ見えます）。
5. 次の2つがそろうと、準備画面へ進みます。協力プレイは2人以上の時だけ出発できます。
   - リーダーが募集を締め切った、または満員になった。
   - パーティーの全員が扉に入った。
6. 準備画面で装備を整えて「準備完了」を押します。装備を変えると、準備完了は解除されます。
7. 全員が準備完了になると、リーダーが「バトル開始」を押せます。

### 協力プレイの強さ

| 人数 | ボスの HP | 範囲攻撃の広さ | 送る回数（1人あたり） |
| --- | --- | --- | --- |
| 2人 | 1.5倍 | 1.15倍 | 1秒に8回 |
| 3人 | 2.0倍 | 1.25倍 | 1秒に6回 |
| 4人 | 2.5倍 | 1.35倍 | 1秒に5回 |

- 広くするのは、次の攻撃の輪や円の大きさだけです。予告の時間は変えないので、安全な所は残ります。
  - 巨大森イノシシ：踏みつけの衝撃波
  - 黒蝕狼：侵蝕波動
  - 魔道ゴーレム：危険床・衝撃波
  - 怨嗟の鎧：風刃
- ボスは攻撃が終わるたびに、生きている人の中からねらう人を選び直します。同じ人は続けてねらいにくくしてあります。
- 1人が倒れても、ほかの人が戦っている間は戦いが続きます。全員が倒れると負けです。
- ボスの HP が 0 になると、全員の勝ちです。
- 勝った時のバトルコインはサーバーが決めて、参加した全員に1回だけ入れます。ボスの基本のコインに、クリアタイムのランクのボーナスが付きます。
  - 始めてから決まった秒数（ボスごとに 20〜25 秒）より早い勝ちには、コインは入りません。
  - 協力プレイのクリアタイムは、マイベストには入りません。

### 通信のしくみ

- **パーティー・扉・準備完了・バトル開始・報酬**：データベースの関数（`hk_mp_*`）で決めます。人数・リーダー・満員などは、サーバーが確かめます。
- **酒場の中の位置・戦いの中の動き**：Supabase Realtime（WebSocket）で、端末どうしで送り合います。データベースには書きません。
  - 酒場：チャンネル `hoshinoko-tavern-<ルーム>`
  - 戦い：チャンネル `hoshinoko-party-<パーティーの id>`
- **戦い**：バトル開始を押したリーダーの端末（ホスト）だけが、ボスを動かします。
  - ボスの HP・攻撃・ねらう人は、ホストが決めます。
  - ほかの人の端末は、ホストから届いたボスの様子を、少し遅らせて同じように出します。
  - ボスへのダメージは、当てた人の端末が計算してホストへ送ります。1回 4000、1人 10秒で 40000 までです。
  - 自分の主人公がボスの攻撃に当たったかは、自分の端末で判定します。
- **ルーム**：1つのルームは16人までです。いっぱいの時は、次のルームへ移ります。同じパーティーの人は、リーダーのルームに集まります。

### 通信が切れた時

- 酒場で通信が切れた人は、ほかの人の画面から数秒で消えます。
- サーバーは、酒場と準備画面では30秒、戦いの中では120秒、何も届かない人をパーティーから外します。
  - リーダーが抜けた時は、いちばん先に入った人が新しいリーダーになります。
  - だれもいなくなったパーティーはなくなります。
- 戦いの中でホストの通信が切れると、ほかの人の戦いは8秒後に「通信が切れました」で終わります（報酬なし）。

### 無料のプロジェクトの Realtime の上限

- 上限は「1秒に100回（送った数と届いた数の合計）」と「1か月に200万回」です。これを超えないように、送る回数をしぼっています。
  - 酒場：動いている間だけ 1秒に4回まで、止まっている時は 2.5秒に1回です。
  - 戦い：上の表の回数です。
- 4人の協力プレイ1つで、だいたい 1秒に80回ぐらい使います。同時に遊べるのは、だいたい4人の戦い1つ、または2人の戦い2〜3つまでです。
- それより多くの人が同時に遊ぶ時は、Supabase の有料プランにするか、専用のサーバーが必要です。

### まだできないこと・制限

- PvP の対戦はまだありません。募集・扉・準備画面まではできます。「対戦開始」を押すと「今後実装予定」と出ます。
- 戦いの途中で通信が切れた人は、同じ戦いに戻れません。
- ホストが切れた時に、ほかの人がホストを引きつぐしくみはありません。
- ホストの端末がボスを決めるので、ホストがゲームを改造すると、ずるができます。報酬は、サーバーの最短時間と1回だけの決まりで守っています。
- チャンネルの名前を知っている人は、だれでもそのチャンネルに入れます。パーティーのチャンネルの名前は、推測できない id で作っています。画面に出すのはプレイヤー名だけで、ユーザー名は出しません。
- 協力プレイは一時停止できません。
- ほかの人の回復の魔法は、見た目だけ出ません（ダメージを与える魔法は見た目が出ます）。
